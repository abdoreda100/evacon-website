# EVACON | موقع إيفاكون العقاري + لوحة إدارة المحتوى

## إيه الجديد؟

الموقع الآن يعمل بـ **Node.js 20+ بدون حزم خارجية**، مع لوحة إدارة واحدة عبر `/admin` تتيح:

- 📩 مشاهدة استفسارات العملاء، وتصديرها CSV.
- 🏡 إضافة وتعديل وحذف الوحدات العقارية: السعر، المساحة، المنطقة، الوصف، المميزات، الصورة، رابط الوحدة.
- 🖼️ رفع الصور بصيغ JPG وPNG وWebP بحد أقصى 3MB للصورة.
- ✍️ تعديل عنوان الواجهة، وصف الشركة، الرؤية، الرسالة، الهدف.
- 🔤 تغيير الخط العربي بين IBM Plex Sans Arabic وCairo وTajawal.
- 🌐 تغيير روابط Facebook وInstagram وWhatsApp، مع زر Facebook عائم.
- ✅ التحكم في شريط التحذير التجريبي وفهرسة Google (لا تفتح الفهرسة إلا مع بيانات حقيقية).
- 💾 تنزيل نسخة احتياطية من محتوى الموقع بصيغة JSON، منفصلة عن CSV طلبات العملاء.

**الصورة الافتراضية للواجهة هي صورة الريسبشن التي قدمتها، بألوانها الطبيعية وبدون فلتر رمادي أو طبقة تظليل.** رابط فيسبوك الافتراضي: https://www.facebook.com/p/Evacon-61594188086644/

## تشغيل المشروع محليًا على Windows

1. فك ضغط الملف وافتح مجلد المشروع الذي يحتوي على `server.mjs` و`package.json`.
2. افتح PowerShell في نفس المجلد.
3. اضبط مستخدم/كلمة مرور قوية. **لا تستخدم كلمة المرور المثال في موقع عام**:

```powershell
$env:ADMIN_USER="admin"
$env:ADMIN_PASSWORD="ChangeToYourOwnStrongSecret2026!"
& "C:\Program Files\nodejs\node.exe" server.mjs
```

4. افتح الموقع `http://localhost:3000` ولوحة الإدارة `http://localhost:3000/admin`.

> لو Node.js متاح على PATH، استخدم `node server.mjs` أو `npm.cmd start`.

## التعديل من داخل لوحة الإدارة

- **طلبات العملاء:** تُعرض البيانات ويُمكن تصدير CSV.
- **إدارة الوحدات:** اضغط «إضافة وحدة جديدة»، املأ البيانات، ارفع الصورة، ثم «حفظ الوحدة». للتعديل/الحذف استخدم أزرار كل وحدة في القائمة. **التغيير يظهر فور تحديث صفحة الموقع؛ لا تحتاج GitHub أو build.py بعد ذلك.**
- **بيانات الشركة:** عدّل الصورة والعناوين والرؤية والرسالة وروابط السوشيال، وحدّد الخط. اضغط «حفظ التعديلات على الموقع».

> راجع الأسعار والبيانات مع فريق الشركة قبل تعطيل وضع التجربة؛ الـ6 وحدات الأصلية ليست عروض بيع حقيقية.

## تخزين البيانات على Railway (مهم جدًا)

أضف **Volume** مربوطًا بخدمة الموقع، على مسار `/data`.

Railway يضيف `RAILWAY_VOLUME_MOUNT_PATH`، والمشروع يستخدمه تلقائيًا لحفظ:

- `leads.json`: استفسارات العملاء الموجودة سابقًا، لن تُحذف بسبب التحديث البرمجي عند استخدام نفس Volume.
- `cms.json`: الوحدات ومعلومات الشركة وروابط السوشيال.
- `media/`: الصور التي ترفعها من لوحة الإدارة.

**لا ترفع الملفات الخاصة ببيانات العملاء أو إعدادات CMS من الـVolume إلى GitHub.**

في Railway اضبط Variables:

```text
ADMIN_USER = admin
ADMIN_PASSWORD = (كلمة سر قوية مكونة من 12 حرفًا على الأقل)
REQUIRE_PERSISTENCE = 1
```

عند `REQUIRE_PERSISTENCE=1`، لو ما فيش Volume، لوحة الإدارة سترفض حفظ تعديلات المحتوى والصور، والفورم سيرفض تسجيل طلبات حتى ما يوهمكش إنها محفوظة. الاستضافة تحتاج Backup دوري، وملفات JSON مناسبة كبداية صغيرة وليست قاعدة بيانات متعددة الخوادم.

## النشر على مشروعك الحالي في GitHub وRailway

1. **احتفظ بنسخة احتياطية** من CSV طلبات العملاء ومن الـVolume قبل تحديث كود الإنتاج.
2. استخدم GitHub Desktop أو Git CLI لرفع **محتويات** المجلد ده إلى المستودع `abdoreda100/evacon-website`، بحيث `server.mjs` و`cms.mjs` يظهرا في الجذر و`assets/admin-cms.js` داخل `assets`.
3. اعمل Commit وPush إلى الفرع `main`.
4. Railway سيُجري Deploy تلقائيًا إذا Auto Deploy متفعّل. افتح Deployments وتأكد من Active.
5. افتح رابط الموقع، ثم أضف `/admin`؛ ستحصل على 3 تبويبات: الطلبات، الوحدات، بيانات الشركة.
6. جرّب تعديل عنوان بسيط، حفظه، ثم تحديث الصفحة الرئيسية. وأعد نشر الموقع للتحقق من ثبات البيانات بعد Redeploy.

للمبتدئ، إرشادات GitHub Desktop في ملف `DEPLOY-RAILWAY.md`.

## ملاحظات أمنية وتشغيلية

- لوحة الإدارة محمية بـHTTP Basic Auth عبر السيرفر؛ لا تستخدمها عبر HTTP عام، وفعّل HTTPS دائمًا (رابط Railway العام يستخدم HTTPS).
- المرفقات المقبولة صور JPG/PNG/WebP حتى 3MB مع تحقق أولي من ترويسة الملف.
- وسائل الحماية الأساسية ليست بديلًا عن قاعدة بيانات، نظام صلاحيات، MFA، نسخ احتياطية وتدقيق أمني قبل التوسع التجاري.
- صفحة سياسة الخصوصية نموذج وتحتاج استكمال بيانات الشركة ومراجعة متطلبات الخصوصية المعمول بها.
- `/api/health` لا يحتاج تسجيل دخول؛ أما `/api/admin/*` فمحمية بكلمة مرور الإدارة.
- `build.py` أصبح قديمًا ولا يُستخدم: عرض الوحدات وصفحات تفاصيلها يتم مباشرة من بيانات CMS عبر Node.
